# `data.models`

Models are Java classes that describe **what we save in the database**. In MongoDB each object becomes one **document** (similar to a row in a SQL table).

## `Delivery`

A package that someone wants to send.

```java
@Data
@Document
public class Delivery {
    @Id
    private String trackingNumber;
    private String name;
    private String description;
    private double weight;
    private String sender;
    private String recipient;
}
```

Here the `trackingNumber` is the id. It is generated by the service (6 random letters and digits, for example `K3D9QZ`), so no two deliveries share the same one.

## `TrackingHistory`

One event in the journey of a delivery, for example "Package Received at Sending Office" or "Out for delivery". A delivery has **many** of these.

```java
@Data
@Document
public class TrackingHistory {
    @Id
    private String id;
    private String trackingNumber;
    private String details;
    @CreatedDate
    private LocalDateTime eventDate;
}
```

`trackingNumber` links an event to its `Delivery`. MongoDB has no strict relationships, so we keep the number and look the events up with it.

## How they fit together

```
Delivery (trackingNumber = K3D9QZ)
   |
   +-- TrackingHistory: "Package Received at Sending Office"
   +-- TrackingHistory: "In transit"
   +-- TrackingHistory: "Delivered"
```

## Annotations

| Annotation | Meaning |
|---|---|
| `@Document` | This class is stored as a MongoDB document. The collection name is the class name in lower camel case, for example `delivery`. |
| `@Id` | The unique identifier of the document. If it is a `String` and left empty, MongoDB creates one for us. |
| `@CreatedDate` | Filled in automatically the first time the object is saved. It needs `@EnableMongoAuditing` in `Main`. |
| `@Data` (Lombok) | Writes the getters, setters, `toString`, `equals` and `hashCode` for us at compile time. This is why you can call `delivery.getSender()` although we never wrote it. |

## Good to know

- Models should **not** be sent straight to the client. We use DTOs (see `dtos`) for that.
- Models contain data only. Rules and logic belong in the `services` package.
